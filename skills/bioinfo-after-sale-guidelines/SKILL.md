# BioInfo_AfterSale AI 辅助开发规范

本规范适用于本仓库中由 AI 协助完成的代码、教程和可视化产物。它是在项目现有代码风格基础上的约束，不替代用户对具体任务的明确要求。

## 可视化与教程产物

1. `docs/` 中的教程 Markdown 执行示例时，默认只生成 PDF；教程文档也只需记录 PDF 输出。除非用户明确要求，不额外生成 PNG、JPG、SVG 或 HTML 图片。

2. `R/` 中的可视化函数脚本按图片内容命名，例如 `PCA.R`、`Venn.R`、`Volcano.R`。除非有特殊原因，不以 `plot` 作为文件名前缀或后缀；只有在内容本身需要区分同类图时才使用更具体的内容名。

3. 本 R 包默认使用 R 进行可视化。确实只能使用 Python 时，必须单独创建 `Python/` 文件夹存放 Python 脚本及其必要说明，不得将 Python 文件混入 `R/`。

4. 每份 `docs/` 教程示例 Markdown 必须包含可直接运行的示例数据生成或读取代码。数据可以是真实数据或模拟数据：
   - 模拟数据必须明确标注为模拟/虚构数据；
   - 真实数据必须注明来源、版本或访问链接；
   - 学术数据必须标明论文、数据库或项目出处，尽可能包含 DOI、 accession 或稳定链接；
   - 示例必须说明输入数据的行列含义、样本标识和关键参数。

5. 可视化 R 函数必须无条件支持 `choose_plot_style.R` 提供的样式对象和统一输出参数。除非图形系统本身不接受 `ggplot2` 修改（例如 `upset` 等带有独立绘图参数的函数），不得绕过统一样式接口。函数应支持样式传入、输出文件和尺寸/DPI配置，并在教程中展示其用法。

6. 当用户提供指定脚本并要求转换为 R 可视化函数时，必须以原脚本的可视化效果为验收基准：完整保留数据变换、分组逻辑、坐标/比例、颜色、图层、标签、图例、主题、输出尺寸和随机种子等可观察行为。不得用简化图、占位图或功能缩水版本冒充转换结果；无法一一复现时，必须明确列出差异和原因。

7. 所有可视化图形默认只使用 Times New Roman（新罗马）字体；函数、教程和生成结果应保持这一字体设置，不混用其他字体。

## 可视化开发补充原则

按以下顺序选择实现方案：复用仓库现有函数与样式 → 使用 R 原生能力或已有依赖 → 最后再增加新依赖或新抽象。只实现当前任务需要的功能，不为未来需求增加包装层、配置项或占位代码。

简化代码不得改变输入矩阵方向、样本分组、数据转换、统计方法、颜色范围、标签、图例、输出尺寸和随机种子。行列名称、分组信息或统计矩阵无法对应时，应明确报错，不得通过删除标签、截断数据或静默重排继续绘图。

修复问题时先检查数据读取、处理、统计和绘图的完整流程；问题来自共享函数时，应在共享函数中修复，避免在多个示例中重复打补丁。

完成后必须实际检查生成的 PDF，而不只是确认代码无报错。重点确认样本名、基因或物种名、分组、图例和颜色映射正确，且不存在标签裁切、重叠、标题越界或空白图层。

## AI 协助开发的四项原则

### Think Before Coding

- 先识别假设、歧义、输入约定和潜在取舍，并在必要时向用户说明。
- 不要静默选择有实质影响的解释；存在多个合理解释时列出选项。
- 发现更简单或更安全的方案时应提出，而不是盲目实现。
- 对不理解的上下文先停下来说明，不在不确定时扩展修改范围。

### Simplicity First

- 只实现请求范围内的最小方案，不添加未要求的功能、抽象或配置项。
- 不为不可能或不相关的场景堆叠错误处理。
- 优先复用仓库已有 helper、样式和示例模式。
- 若明显可以大幅减少代码而不损失行为，应选择更简单的实现。

### Surgical Changes

- 只修改完成目标所必需的文件和行；不顺手重构邻近代码、注释或格式。
- 遵循现有命名、接口和代码风格，即使个人偏好不同。
- 只清理由本次修改造成的未使用导入、变量或函数；预存的无关问题只报告不删除。
- 每一处改动都应能追溯到用户请求或可验证的修复。

### Goal-Driven Execution

- 开始前写出简短成功标准，例如“4 个教程代码块均可运行并在 `docs/` 生成 4 个 PDF”。
- 先建立可复现的检查，再实现修改；修复 bug 时优先添加能复现问题的测试。
- 完成后运行与风险匹配的验证：R 语法解析、示例执行、输出文件存在性、尺寸/格式检查及必要的测试。
- 如果验证失败，继续定位并修复，或明确报告阻塞原因，不以“看起来可以”作为完成标准。

## 默认执行清单

1. 检查目标文件、现有接口、未提交改动和输入数据来源。
2. 明确假设与成功标准，确认输出格式默认是 PDF。
3. 选择符合内容的 R 文件名；只有 Python 不可替代时才使用 `Python/`。
4. 实现最小改动，并接入 `choose_plot_style.R`。
5. 为每个公开可视化函数提供同名教程 Markdown 和可运行示例数据。
6. 执行示例并验证 PDF 输出、函数返回值和关键统计/分组结果。
7. 汇报修改文件、验证命令、结果以及仍存在的限制。
